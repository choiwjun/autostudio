# 11. 운세 채널 + 수익화 로드맵 — 만세력 엔진 이식 · 자체 블로그 · 네이버쇼핑커넥트

> 상태: 계획 확정 (2026-08-10) · 관련 저장소: `autostudio`(콘텐츠 공장), `myunglab`(만세력 엔진)
> 쇼츠 공장은 네이버 블로그 + 외부 블로그 안정화 이후 별도 검토 (본 계획 제외)

## 1. 배경과 목적

- **autostudio** — 네이버 애드포스트 키워드 발굴·초안 자동화 (Python/FastAPI, Vercel+Supabase). 발굴·생성은 자동이지만 게시는 수동.
- **myunglab (命 MYEONG)** — 만세력 엔진 기반 사주/궁합/운세 상용화 수준 구현 (TypeScript, Next.js + Tauri 데스크톱 설치형). 12종 계산, 골든 픽스처·외부 제공자 비교·전문가 검증 프로세스 보유. 도메인 `myeong.kr` 확보, 웹 배포 미실시.
- **목적 ①** — 게시 병목 해소로 즉시 수익화 (출구 뚫기 + 카테고리 리밸런싱 + 네이버쇼핑커넥트)
- **목적 ②** — 운세 콘텐츠 자동화로 초기 트래픽 확보 + myunglab 홍보·전환 채널

### 현재 상태 점검 (2026-08-10)
- 초안 34개 대기 / 발행 1개 — 발굴·생성은 자동, **게시(출구)가 막혀 수익 미발생**
- 활성 204개 중 요리 84개(42%) — CPC 0.5로 최저, 수익 병목
- v20 완료: '곧 뜰' 프리셋(선점 신호), 카테고리별 신선도 창, 베이지안 CPC 스무딩, 점수 정규화 재조정(0.15/0.02)

### 검증된 판단
- 운세는 CPC가 낮아 **광고 수익원으로는 부적합**하나, **플랫폼 전환(홍보) 채널로는 반복 검색 수요(오늘의/주간/월간 운세)가 강력**.
- AI 환상 운세는 저품질 위험이나 **만세력 엔진 실계산 + AI 해석**은 차별화와 E-E-A-T 확보.
- 엔진은 순수 TypeScript(플랫폼 독립) — autostudio(Python)와 통합하려면 **Python 포팅** 필요.

## 2. 수익화 로드맵 (5가지 검증 결과)

| # | 방안 | 판정 | 근거 |
|---|---|---|---|
| 1 | **출구 뚫기 (게시 큐)** | ✅ 즉시 실행 | 플래너(`/planner`)·플랫폼별 내보내기(`publish.py`) **이미 구현됨**. 부족한 건 발행 리마인더/체크리스트뿐. *참고: "34개 = 주24회 기준 23개월치"는 계산 오류 — 실제 1.4주치* |
| 2 | **카테고리 리밸런싱** | ✅ 즉시 실행 | `DEFAULT_FOCUS_SEEDS`에 고CPC(보험/금융 1.0, 부동산/법률 0.9) 이미 존재. 시드 비중 조정 + **발굴 카테고리 비중 가드**로 같은 글 수 대비 수익 상승. *"1.5~2배"는 보장 수치 아님* |
| 3 | **네이버쇼핑커넥트 (어필리에이트)** | 🔶 중간 규모 | **네이버 공식 프로그램 — 네이버 블로그에서 허용** (쿠팡은 감점 리스크로 기각). 기존 `NAVER_CLIENT_ID/SECRET`으로 쇼핑 검색 API 호출 가능. 파트너스 ID 필요 |
| 4 | 리드 판매 (보험/대출/청약) | ⏸ 보류 | 단가(건당 2~5만)는 타당하나 네이버 정책 위반 소지 + 보험 모집 규제 + 제휴처 필요. 외부 랜딩 인프라 선행 필수 |
| 5 | SaaS / 데이터 상품 | ⏸ 보류 | 데이터 수집만 구현됨(리포트·구독·결제·발송 미구현). 멀티테넌트 전환 작업량 큼 + **실적 증명 부족** — 성과 축적 후 |

## 3. 최종 구조

```
autostudio (Vercel + Supabase) — 콘텐츠 공장 + 외부 블로그
├── 수익화 (Phase A·B)          출구 뚫기 · 리밸런싱 · 쇼핑커넥트 상품 블록
├── engine/                  만세력 Python 포팅 (Phase 1)
│   ├── calendar.py          간지·절기·음양력·한국시간 규정
│   ├── fortune.py           daily-fortune(일운)·monthly-rhythm(월운)
│   └── data/                lunar-solar·solar-terms (SQLite 테이블 권장)
├── /blog                    자체 블로그 (Phase 2)
│   ├── blog_posts 테이블 + 목록/상세 페이지
│   └── sitemap.xml · RSS · OG · JSON-LD
├── daily-collect            발굴 → 초안 → /blog 자동 발행
└── 운세 채널 (Phase 3)       엔진 직접 호출 → 운세 글 매일 재생성·발행 + CTA

myunglab (기존, 변경 없음) — 데스크톱 설치형 판매 + myeong.kr 랜딩
```

### 의존 순서
```
Phase A·B(수익화) → Phase 1(엔진 포팅) → Phase 3(운세 자동화)
Phase 2(/blog)는 Phase 1과 병행 가능
쇼츠 공장: 안정화 후 별도 계획 (본 문서 제외)
```

## 4. Phase A — 즉시 실행: 출구 뚫기 + 카테고리 리밸런싱 (작업량 소)

| # | 작업 | 산출물 |
|---|---|---|
| A.1 | 발행 리마인더/체크리스트 + **게시 로그** | 플래너에 발행 대상 알림(생성 3일+ 미발행 초안 강조) + 발행 절차 체크리스트(내보내기→URL 등록→성과 기록) + **게시 기록(발행일·블로그) 컬럼·완료 표시** — 34개 소진 추적 |
| A.2 | 시드 리밸런싱 (요리는 실험 카테고리로 재정의) | `DEFAULT_FOCUS_SEEDS`에서 요리 계열 축소, 보험/금융/부동산/법률 시드 확대. **기존 요리 84개·초안은 쇼핑커넥트 실험 자산으로 유지** (B.3과 정합) |
| A.3 | 발굴 카테고리 비중 가드 | `collect.discover`에 카테고리 비중 상한(예: 활성의 30%) — 초과 시 해당 카테고리 신규 발굴 제한 |
| A.4 | **'곧 뜰' 프리셋 → 초안 우선순위 연결** | `content_batch.keywords_without_drafts` 정렬을 v20 upcoming 프리셋 조건 기반으로 — 경쟁 붙기 전 선점 생성 |

## 5. Phase B — 네이버쇼핑커넥트 상품 블록 (중간 규모)

| # | 작업 | 산출물 |
|---|---|---|
| B.1 | 상품 검색 모듈 | `naver_client.py` 확장 — 네이버 쇼핑 검색 API (기존 키 사용) → 키워드별 상품 3개 |
| B.2 | 링크 변환 | 상품 링크 → 네이버쇼핑커넥트 딥링크(파트너스 ID) — `SHOPPING_CONNECT_PID` 설정값 |
| B.3 | 초안 상품 블록 | `draft_pipeline`에 상품 블록 삽입 — 요리/패션/IT 카테고리 우선 (글 하단 "관련 상품") |
| B.4 | 렌더링 | `publish.py` 플랫폼별 포맷에 상품 링크·가격 렌더링 (네이버: 링크+가격 텍스트) |

### 선행 조건
- 네이버쇼핑커넥트 가입 + 파트너스 ID 발급 (미발급 시 B.1까지 진행, 링크는 자리 표시)
- 애드포스트 계정과 쇼핑커넥트 병행 가능 여부 확인
- 요리·패션·IT 기존 초안이 상품 블록 실험 대상 (A.2의 요리 자산 재정의와 정합)

## 6. Phase 1 — 만세력 엔진 Python 포팅

| # | 작업 | 산출물 | 비고 |
|---|---|---|---|
| 1.1 | 데이터 변환 | `lunar-solar.generated.json`(4MB)·`solar-terms.generated.json`(1.1MB) → **SQLite 테이블** | 인덱스·조회·캐시 용이, DB 인프라 재활용 |
| 1.2 | core 포팅 | `ganji`·`solar-terms`·`lunar-solar`·`korean-legal-time`·`manseryeok-engine` → Python | 결정적 계산이라 1:1 이식 |
| 1.3 | 운세 문구 포팅 | `daily-fortune`(305줄)·`monthly-rhythm`(232줄) → Python + **별자리·띠별 문구 규칙 별도 세트** (엔진 밖 규칙 — 3.1 콘텐츠 타입용) | 규칙 기반·결정적·금지어 가드 유지 |
| 1.4 | 정확성 검증 | myunglab golden-fixtures → Python 테스트 재사용 | 상용화 정확도 이식 보장 |
| 1.5 | 사주 4기둥(2단계) | `saju/calculator` + 십신·신살·용신·대운 | 심화 콘텐츠용 (이번 범위 밖) |

### 기술 결정
- **경로 1(Python 포팅) 채택** — 서버리스(Vercel)와 GH Actions 배치가 같은 엔진 공유. Node 런타임 실행은 Vercel에서 불가해 비채택.
- **데이터는 SQLite 테이블** — 4MB JSON을 메모리 로드하지 않음.
- **검증은 픽스처 재사용** — myunglab golden-fixtures가 Python 테스트의 golden standard.

- **myeong.kr 랜딩 미니 페이지** — 데스크톱 다운로드 + 구매 CTA (Vercel 정적 1페이지, ~1~2시간). CTA 전환이 성립하려면 필수
- 쇼핑커넥트 상품 블록(B.3)과 운세 글은 **동시 삽입 금지** (운세 글은 CTA만)

- 네이버 블로그는 애드포스트(고CPC) 전용 유지 — 도메인 파워 혼재 방지.
