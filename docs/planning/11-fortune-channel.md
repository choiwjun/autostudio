# 11. 운세 채널 + 수익화 로드맵 — 만세력 엔진 이식 · 자체 블로그 · 네이버쇼핑커넥트

> 상태: 계획 확정 (2026-08-10) · 관련 저장소: `autostudio`(콘텐츠 공장), `myunglab`(만세력 엔진)
> 쇼츠 공장은 네이버 블로그 + 외부 블로그 안정화 이후 별도 검토 (본 계획 제외)

## 1. 배경과 목적

- **autostudio** — 네이버 애드포스트 키워드 발굴·초안 자동화 (Python/FastAPI, Vercel+Supabase). 발굴·생성은 자동이지만 게시는 수동.
- **myunglab (命 MYEONG)** — 만세력 엔진 기반 사주/궁합/운세 상용화 수준 구현 (TypeScript, Next.js + Tauri 데스크톱 설치형). 12종 계산, 골든 픽스처·외부 제공자 비교·전문가 검증 프로세스 보유. 도메인 `myeong.kr` 확보, 웹 배포 미실시.
- **목적 ①** — 게시 병목 해소로 즉시 수익화 (출구 뚫기 + 카테고리 리밸런싱 + 네이버쇼핑커넥트)
- **목적 ②** — 운세 콘텐츠 자동화로 초기 트래픽 확보 + myunglab 홍보·전환 채널

### 현재 상태 점검 (2026-08-10)
- 초안 34개 대기 / 발행 1개 — 발굴·생성은 자동, **게시(출구)가 막혀 수익 미발생**
- 활성 204개 중 요리 84개(42%) — CPC 0.5로 최저, 수익 병목
- v20 완료: '곧 뜰' 프리셋(선점 신호), 카테고리별 신선도 창, 베이지안 CPC 스무딩, 점수 정규화 재조정(0.15/0.02)

### 검증된 판단
- 운세는 CPC가 낮아 **광고 수익원으로는 부적합**하나, **플랫폼 전환(홍보) 채널로는 반복 검색 수요(오늘의/주간/월간 운세)가 강력**.
- AI 환상 운세는 저품질 위험이나 **만세력 엔진 실계산 + AI 해석**은 차별화와 E-E-A-T 확보.
- 엔진은 순수 TypeScript(플랫폼 독립) — autostudio(Python)와 통합하려면 **Python 포팅** 필요.

## 2. 수익화 로드맵 (5가지 검증 결과)

| # | 방안 | 판정 | 근거 |
|---|---|---|---|
| 1 | **출구 뚫기 (게시 큐)** | ✅ 즉시 실행 | 플래너(`/planner`)·플랫폼별 내보내기(`publish.py`) **이미 구현됨**. 부족한 건 발행 리마인더/체크리스트뿐. *참고: "34개 = 주24회 기준 23개월치"는 계산 오류 — 실제 1.4주치* |
| 2 | **카테고리 리밸런싱** | ✅ 즉시 실행 | `DEFAULT_FOCUS_SEEDS`에 고CPC(보험/금융 1.0, 부동산/법률 0.9) 이미 존재. 시드 비중 조정 + **발굴 카테고리 비중 가드**로 같은 글 수 대비 수익 상승. *"1.5~2배"는 보장 수치 아님* |
| 3 | **네이버쇼핑커넥트 (어필리에이트)** | 🔶 중간 규모 | **네이버 공식 프로그램 — 네이버 블로그에서 허용** (쿠팡은 감점 리스크로 기각). 기존 `NAVER_CLIENT_ID/SECRET`으로 쇼핑 검색 API 호출 가능. 파트너스 ID 필요 |
| 4 | 리드 판매 (보험/대출/청약) | ⏸ 보류 | 단가(건당 2~5만)는 타당하나 네이버 정책 위반 소지 + 보험 모집 규제 + 제휴처 필요. 외부 랜딩 인프라 선행 필수 |
| 5 | SaaS / 데이터 상품 | ⏸ 보류 | 데이터 수집만 구현됨(리포트·구독·결제·발송 미구현). 멀티테넌트 전환 작업량 큼 + **실적 증명 부족** — 성과 축적 후 |

## 3. 최종 구조 (B2B/B2C 분리)

```
myunglab (사주/운세 엔진 + 제품)
├── B2B — 데스크톱 앱 (전문가용, 라이선스) [기존, 유지]
│   └── 마케팅: 역학 커뮤니티 + 벤치마크 콘텐츠(블로그가 근거) + 체험판/데모
└── B2C — 웹 서비스 (일반인용) [신규 — 최소 배포 선행]
    └── myeong.kr: 사주/궁합 리포트 + NicePay 결제 (코드 이미 존재, env 활성화)

autostudio (Vercel + Supabase A) — 콘텐츠 공장 (B2B·B2C 양쪽 지원)
├── 수익화 (Phase A·B)          출구 뚫기 · 리밸런싱 · 쇼핑커넥트 상품 블록
├── B2B 콘텐츠                  벤치마크 비교·전문가 가이드 (자동 생성)
├── engine/                  만세력 Python 포팅 (Phase 1 — 완료)
├── daily-collect            발굴 → 초안 → 운세 글 생성
└── 발행 클라이언트             콘텐츠/운세 글 → [블로그 발행 API] HTTP 전송

별도 블로그 앱 (별도 Vercel + Supabase B + 별도 도메인 — 신규 저장소)
├── POST /api/posts          발행 수신 (토큰 인증) → blog_posts 저장
├── / (공개)                 목록(카드)·상세(마크다운→HTML)
├── sitemap.xml · RSS · OG   SEO
└── 운세 글·B2B 콘텐츠 호스팅   SNS 요약본의 랜딩
```

### 채널별 수익화 정리

| 채널 | 대상 | 수익화 |
|---|---|---|
| B2B 데스크톱 (기존) | 사주 전문가 | 라이선스 판매 (커뮤니티·벤치마크 콘텐츠·데모) |
| B2C 웹 (신규) | 일반인 | 사주/궁합 리포트 구매 (NicePay) — 사용자 구축 |
| **별도 블로그 (신규)** | 일반인·전문가 | 운세·B2B 콘텐츠 호스팅 — SNS 유입 랜딩, 광고·CTA 수익 (추후) |
| 운세 쇼츠 (B2C 웹 출시 후) | 일반인 | 웹 리포트 유입 → 구매 + 유튜브 광고(소) |
| KDP 책·쇼츠 (영어권) | 영어권 독자 | 아마존 로열티 + 어필리에이트 |

### 의존 순서
```
Phase A·B(수익화) → Phase 1(엔진 포팅 — 완료) → Phase 2(별도 블로그 앱)
→ Phase 3(운세 자동화 — 생성 + 발행 API) → ③운세 쇼츠 → Phase K(KDP)
쇼츠 공장: B2C 웹 출시 후 (본 문서 제외는 KDP·운세 쇼츠 한정 해제)
```

### 기술 결정
- **경로 1(Python 포팅) 채택** — 서버리스(Vercel)와 GH Actions 배치가 같은 엔진 공유. Node 런타임 실행은 Vercel에서 불가해 비채택.

## 8-1. 운세 콘텐츠·프롬프트 설계 (v22.2 확정)

### 생성 원칙 — "엔진 = 데이터, LLM = 통역사"
- myunglab 엔진이 **계산**(간지·일간·에너지·운세 문구 — 결정적, 변형 금지) 담당
- LLM 프롬프트는 **의미 방향을 유지한 채 일상 언어로 풀어쓰기**만 담당
- **전문용어 금지** (간지·십신·일간 등) — 일반인 독자 기준
- 금지어 가드(myunglab: 반드시/무조건/100%) + 단정 표현 + 기준일(신선도) 검수 재사용

### 2가지 프롬프트 (퍼널: SNS → 블로그)

**프롬프트 A — SNS 요약본** (인스타/커뮤니티용)
- 엔진 그라운딩(일간 에너지·핵심 문구·분야별) 주입 → 500자 이내 카드 문구
- 구조: 후킹 1문장 → 일상어 3~5문장 → 분야별 한 줄(재물/애정/건강) → 행운 요소 1줄
- **CTA: "더 자세한 오늘의 운세는 블로그에서 확인하세요"** (SNS → 블로그 유입)
- 출력 JSON: text + hashtags

**프롬프트 B — 블로그 상세본** (별도 블로그 앱 업로드용)
- 동일 엔진 그라운딩 + 월운/주간 데이터 → 2,500~3,500자 구조화 글
- 구조: 제목(날짜+키워드) → 한줄 요약 → 총평 → 분야별 상세(재물/애정/건강/일) → 행운 아이템 → 실천 가이드 → 마무리
- **CTA: 블로그 내 다른 운세 글/구독 유도** — myeong.kr 리포트 구매는 보류 (B2C 웹 출시 후 재검토)
- v19 플랫폼 파이프라인 재사용 (markdown, 별도 블로그 앱 전용)

### 검수 추가 항목
- 전문용어 검출(간지·십신·일간...) → 재생성 지시
- 그라운딩 정합 — 엔진 에너지 방향(긍정/부정)과 본문 톤 일치
- SNS본: 500자 상한 / 블로그본: 구조 섹션 충족

### 범위·시점 명시
- **이번 범위: 생성까지만** — SNS(인스타/커뮤니티) 발행 자동화는 추후 과제. 블로그 발행은 **발행 API 연동**(Phase 2.5~2.6)으로 자동화
- **myeong.kr 리포트 CTA·리드 폼**: 사용자가 B2C 웹(myunglab) 구축 완료 후 연동 작업 진행 (보류)
