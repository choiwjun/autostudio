## 1. 설계 원칙

1. **밀도 우선 (파워 유저 도구)** — 하루 1,000개 키워드를 스캔·판단하는 PC 도구. 카드형이 아닌 테이블 중심, 한 화면에 정보 최대화
2. **점수는 신호** — 점수는 프록시이므로 숫자 + 뱃지 + 원시값(총 글 수·상품 수·평균가)을 함께 노출해 사용자가 직접 판단
3. **상태 투명성** — "데이터 쌓는 중 / 수요 미확증 / 부분 갱신 / 실행 잠금 / 수집 밀림" 등 파이프라인 상태를 은폐하지 않고 정직하게 표시
4. **실수 방지** — 쓰기 동작(수집·제외·시드)은 토큰 필수, 401은 안내 문구로 즉시 피드백
5. **모바일은 2차** — 최소 폭 1024px 보장. 모바일 전용 뷰는 v1.5

## 2. 정보 구조 (IA)

단일 페이지 + 오버레이 2종(상세 모달, 시드 관리 모달). 3줄 영역:

```
[헤더]        타이틀 | 수집 실행 버튼 | 파이프라인 상태(키워드 N · 시드 N · 마지막 성공 수집)
[컨트롤 바]   분야 ▼ | 상업성 ▼ | 발견기간 ▼ | 키워드 검색 | [제외 포함] | [유망 프리셋] | 시드 관리 | 토큰 입력 · 저장
[본문]        키워드 테이블 (11컬럼, sticky header) + 페이징
[오버레이]    상세 모달 (추이 그래프 + 원시값) / 시드 관리 모달
```

## 5. 컴포넌트 상태 명세

### 5.1 수집 실행 버튼 + 응답 피드백

| 단계 | 버튼 상태 | 상태바 문구 |
|---|---|---|
| idle | "지금 수집 실행" | - |
| 실행 중 | 스피너 + "수집 중..." (비활성) | "수집 실행 중... (최대 45초)" — v2: 스펙 v3 §4.9의 전 구간 예산 반영 (v1의 "최대 60초"는 Vercel 한도일 뿐 수집 예산이 아님) |
| done | 복귀 | "완료: 신규 N개 / 스냅샷 M개 / 오류 E개" — **완료 후 목록·상태바 자동 갱신** |
| partial | 복귀 | "시간 예산 내 일부만 갱신 (스냅샷 N개) — 나머지는 매일 아침 자동" |
| locked | 복귀 | "이미 수집이 실행 중입니다 — 잠시 후 새로고침" |
| 401 | 복귀 | "토큰이 올바르지 않습니다 — 토큰 입력 후 저장" (danger) |
| timeout/네트워크 | 복귀 | "요청이 시간 초과됐을 수 있습니다 — 전체 수집은 매일 아침 자동 실행" (danger) |

### 5.2 파이프라인 상태바 (헤더 우측)

- 정상: `키워드 N개 · 시드 N개 · 마지막 성공 수집 2026-08-03`
- 경과 **2일 초과**: danger색 + `⚠ 수집이 밀려 있습니다 (Actions/Supabase 상태 확인)`
- 이력 없음: `수집 이력 없음` (보조색)

### 5.3 테이블 행

- hover: 배경 `#f5f7fa` / 클릭(행) → 상세 모달, 액션 버튼은 `stopPropagation`
- 기회점수 NULL → "쌓는 중" (보조색, 흐림) — 빈 값이 아닌 **진행 중 상태**로 표현
- 증감률: `▲ +2.1%` 초록 / `▼ -0.5%` 빨강 / NULL "-"
- 수요지수 NULL → "-" 흐림
- **제외된 행**: 전체 opacity 0.45 + 키워드 옆 "제외됨" 뱃지, 액션은 "복원"

### 5.4 상세 모달

- 헤더: 키워드(18px/700) + 권장 뱃지 + 닫기 ✕
- 본문: Chart.js 이중 축 — 좌축: 기회점수(0~100)·수요지수×100, 우축: 총 글 수·쇼핑 상품 수
- 하단: 원시값 요약 칩 4개 (총 글 수 / 쇼핑상품 / 평균가 / 상위글 신선도)
- 닫기: ✕ 버튼 / **Esc** / 배경 클릭
- 오류: 404(키워드 미존재·삭제) → "키워드를 찾을 수 없습니다" + [목록으로 돌아가기] / 네트워크 오류 → [다시 시도] — 모달 내 오류 패널로 표시

### 5.5 빈 상태 / 로딩 / 오류

| 상태 | 표시 |
|---|---|
| 데이터 없음 | 아이콘 + "아직 데이터가 없습니다" + 보조 문구 "시드 추가 후 '지금 수집 실행' (점수는 2일차부터)" + CTA 버튼 2개 [시드 추가] [지금 수집 실행] — **전체 데이터가 0건일 때만 표시** |
| 검색/필터 결과 0건 | "검색 결과가 없습니다 — 필터를 조정하거나 [필터 초기화]". 판별: 데이터는 있으나 검색어·분야·발견기간·상업성 필터 조합 결과가 0건 (온보딩 카피 금지) |
| 첫 로드 | 스켈레톤 테이블 (펄스 애니메이션, 컬럼 골격 유지) |
| API 오류 | "데이터를 불러오지 못했습니다" + [다시 시도] |

## 6. 인터랙션 명세

- **정렬**: 컬럼 헤더 클릭 토글 — 1회 내림차순, 2회 오름차순. 활성 컬럼에 ↑/↓ 화살표 + `aria-sort`, 기타 컬럼에 흐린 ⬍. API 계약: `sort` + `sort_dir=desc|asc` (v2 — API에 방향 파라미터 없으면 토글 불가)
- **필터**: 분야·상업성·발견기간·유망 프리셋 변경 시 페이지 1로 리셋. 발견기간은 API `discovered_within`(최근 7/30일)으로 전달. 유망 프리셋은 API `preset=promising`(기회≥70 & 상업성≥60 & 수요지수≥0.01)으로 전달 — 서버 필터 (v2)
- **필터 초기화**: "검색 결과 0건" 화면의 [필터 초기화] → 검색어·분야·상업성·발견기간·제외 포함 모두 해제 후 1페이지로
- **검색**: 300ms 디바운스, 검색 중 보조 문구 "검색 중..."
- **페이징**: [이전] [다음] + `N건 · X/Y페이지`. 첫/끝 페이지에서 버튼 비활성
- **제외/복원**: 클릭 즉시 PATCH → 목록 새로고침. 확인 다이얼로그 없음(즉시 복원 가능하므로). 401이면 토큰 안내
- **시드 관리 모달**: 목록 + [추가] → 성공 시 목록 갱신·입력 초기화, 삭제는 행 내 버튼
- **토큰**: 저장 시 "토큰 저장됨" 안내 2초 후 소거, 입력창은 `type=password`
- **상세 모달**: 행 클릭 → 열기, 재클릭 시 차트 갱신(기존 인스턴스 destroy)

## 7. 접근성 & 보안

- 테이블: `th scope="col"`, 정렬 컬럼 `aria-sort`
- 뱃지는 **색 + 텍스트 이중 정보** (색맹 대응)
- 대비 4.5:1 이상, `:focus-visible` 스타일
- 외부 유래 문자열 전부 `esc()` 이스케이프 (스펙 §4.10 XSS 방지)
- 쓰기 요청 Bearer 토큰 — 401 응답 공통 처리 함수(`api()`)로 일원화

## 8. 지표 연계 (스펙 §2)

- 컨트롤 바에 **"유망" 프리셋 버튼**: 기회 ≥ 70 & 쇼핑클릭 ≥ 0.5 & 수요지수 ≥ 0.01 (v3) → 4주 지표("유망 키워드 주 10개")를 화면에서 바로 확인. **API `preset=promising` 서버 필터로 구현** (v2 — 클라이언트만 필터하면 페이지 전체에서 일관되지 않음)
- 권장 뱃지 임계값은 초기값 — §2 지표로 조정될 수 있으므로 **뱃지 로직은 프론트 상수로 분리**
