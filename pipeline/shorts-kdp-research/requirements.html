1. 배경 (실측 현황)

1.1 쇼츠 파이프라인 (14-shorts-pipeline.md — 기획 초안, 구현 전)

  • 핵심 차별점: 네이버 인기키워드(블로그 검색)가 아니라 유튜브 인기 주제·채널·키워드 기반 발굴 — "유튜브에서 뜨는 주제 = 쇼츠 소재"
  • 현재 구조: 유튜브 데이터 수집(API v3 우선, 무료 스크래핑/yt-dlp 보조) → 주제 후보 판정(조회/구독·성장률·반응비 + 틈새) → 쇼츠 스크립트 생성(30~45초, 후킹, CTA) → 수동 업로드
  • 데이터 모델: youtube_raw · shorts_topics · shorts_scripts (SQLite/Postgres 이중 SQL 패턴 재사용)
  • 실행 순서: S-1 수집 → S-2 주제 판정 → S-3 스크립트 → S-4 배치+대시보드 → 파일럿(인기 주제 10개 소재 → 5개 쇼츠)
  • 부족한 점: 시장 근거(왜 유튜브인가·규모·경쟁·수익화 경로)가 수치로 제시되지 않음, 파일럿 선정 근거 부재, 수익 모델 미정의

4. 핵심 문제 & 페인포인트

  1. 데이터 소스 궁합: 네이버 인기키워드(블로그 검색)는 쇼츠 소재와 궁합이 낮음 — 쇼츠는 조회·시청 완료율이 지표이고 주제는 유튜브 트렌드에서 나옴
  2. 시장 근거 부재: 쇼츠 초안에 "왜 유튜브인가·시장 규모·경쟁·수익화 경로"가 출처 있는 수치로 없음
  3. KDP 문서 결함: 정책 한도 혼용·의존성 미기재·QC 미정의·파일럿 근거·수익 모델 등 8건
  4. 문서 간 단절: 쇼츠↔KDP↔운세 시너지가 어떤 문서에도 구체적으로 정의 안 됨 (11-fortune §9는 이연만 언급)
  5. 이연 상태: 한국어 운세 쇼츠·영어권 KDP 쇼츠가 "나중에"로 미뤄져 있어 실행 계획 부재

5. 범위

포함

  • 쇼츠 기획: 데이터 소스(API v3 우선·스크래핑/yt-dlp 보조·네이버 보조), 수집 로직, 주제 판정 지표(조회/구독·성장률·반응비·틈새), 스크립트 생성(30~45초·후킹·CTA·검수), 데이터 모델, 배치/발행(수동), 실행 순서, 리스크 — 전부 자료조사 기반으로 고도화
  • KDP 기획: 개선점 8건 전부 반영 + 시장·정책 근거 보강
  • 시너지: KDP↔쇼츠(책 챕터 → 쇼츠 → 아마존 링크), 운세엔진↔쇼츠(운세 카드 쇼츠), 11-fortune §9 개정
  • 파일럿 설계: 쇼츠·KDP 각각 파일럿 주제 선정 기준과 후보 (리서치 결과 기반)
  • 수익 모델: 쇼츠(광고/유입) · KDP(로열티·가격·손익분기) 근거 있는 수치로 명시

제외

  • 코드 구현 (신규 모듈 작성)
  • 자동 업로드/발행 (수동 유지)
  • 실제 데이터 수집·파일럿 실행
  • B2C 웹·SaaS·리드 판매 등 11-fortune §9의 다른 보류 항목
